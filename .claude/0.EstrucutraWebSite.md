# Análisis de la Estructura del Sitio Web — GITMateriasUdeA

> Documento generado a partir del análisis del repositorio `GITMateriasUdeA`. Sirve como
> referencia rápida de arquitectura, organización de archivos y convenciones del sitio.

## 1. Resumen general

- **Tipo de sitio:** sitio web estático puro (HTML/CSS/JS plano). **Sin build step, sin
  framework, sin bundler, sin dependencias de npm** — se sirve el contenido tal cual está
  en el repositorio.
- **Propietario/autor:** Juan Felipe Quintana Gómez, docente de Ingeniería de Sistemas
  (Universidad de Antioquia) y Senior Technical Consultant (Azure/.NET/Arquitectura).
- **Propósito:** portal de material de clase organizado por asignatura, más una página de
  perfil profesional. Incluye índices de curso, decks de diapositivas navegables en el
  navegador y PDFs descargables de cada presentación.
- **Dominio de marca:** `profejuanfe.dev`.
- **Hosting/CI-CD:** Azure Static Web Apps, desplegado automáticamente vía GitHub Actions
  (`.github/workflows/azure-static-web-apps-polite-beach-064318f0f.yml`) en cada push a
  `main`. El job usa `Azure/static-web-apps-deploy@v1` con `skip_app_build: true` (no hay
  paso de compilación, se sube el contenido directo — `app_location: "./"`,
  `output_location: "."`).
- **Configuración de la SWA:** `staticwebapp.config.json` solo define
  `globalHeaders: { "Cache-Control": "no-cache" }` — no hay rutas, fallback ni auth
  configurados.
- **Tamaño aproximado del repo:** ~23 MB en total. La mayor parte corresponde a
  `calidad-de-software/` (~7.7 MB, principalmente PDFs) y `tecnicas-de-programacion/`
  (~1.6 MB).

## 3. Patrón de carpeta por asignatura

Cada asignatura sigue exactamente la misma convención (definida y documentada en el propio
`README.md` del repo):

```
<curso>/
├── index.html                 Índice del curso (agrupado por semana/sesión)
├── topics.js                  Fuente de datos: array TOPICS con week/slug/title/subtitle/available
├── pdfs/
│   └── <slug>.pdf             PDF exportado de cada presentación (una página por slide)
└── presentaciones/
    └── <slug>/
        ├── index.html         El deck de diapositivas (secciones .slide)
        └── img/*.svg          Íconos SVG recoloreados, propios de ese deck
```

- **`arquitectura-de-software/`** y **`diseno-y-analisis-2/`** solo tienen `index.html` +
  `topics.js` — cursos placeholder, marcados como "Próximamente" en el home y sin
  `pdfs/` ni `presentaciones/` todavía.
- **`tecnicas-de-programacion/`**: 4 presentaciones (`presentacion-del-curso`,
  `introduccion-a-la-programacion`, `operadores-aritmeticos-y-ciclos`,
  `topicos-generales-ingenieria-software`), cada una con su PDF e íconos propios.
- **`calidad-de-software/`**: el curso más desarrollado, 13 presentaciones (semana 0 a 12),
  cada una con su carpeta `presentaciones/<slug>/img/` de SVGs propios y su PDF en
  `pdfs/`.

`main.js` lee `topics.js` y agrupa automáticamente por `week` para construir el índice del
curso; `deck-nav.js` lee el mismo `topics.js` dentro de cada deck para poblar el selector
de navegación entre presentaciones (anterior/siguiente/salto directo), filtrando solo las
entradas con `available: true`. Esto significa que **agregar una fila a `topics.js` conecta
automáticamente** la nueva sesión a toda la navegación del curso sin tocar otros archivos.

## 5. Sistema de diseño — "hoja de plano" (blueprint sheet)

Estética consistente en todas las páginas, inspirada en planos arquitectónicos:

- Fondo con grid de líneas finas y marcas de registro (cruces) en las esquinas
  (`.reg-mark`).
- "Title-block" tipo carátula de plano con campos Docente / Enfoque / Semestre / Código.
- Tipografía: **Space Grotesk** (títulos) + **IBM Plex Mono** (etiquetas/números),
  cargadas desde Google Fonts.
- Marca de navegación: recuadro de texto **"JF"** (no el logo institucional de la UdeA),

## 6. Visor de diapositivas (`slides.css` + `slides.js`)

- Cada deck es un HTML con secciones `<section class="slide" id="sNN">` dentro de
  `#deck-stage`.
- `slides.js` calcula en cada resize el mayor rectángulo 16:9 que cabe en pantalla
  (`sizeFrame()`) y lo aplica inline a cada `.slide` (evita bugs de `aspect-ratio` +
  posicionamiento absoluto); maneja navegación por teclado/flechas/swipe/hash de URL; y
  dibuja anotaciones de esquina ("UDEA · 1803" / "CÓDIGO {código}/S{n}") leyendo
  `data-sheet="XXXXXXX"` de `#deck-stage`.
- `@media print` en `slides.css` redefine el layout para exportar a PDF: quita marco/grid,
  un slide por página a 1280×720, reduce fuentes/íconos.
- Los PDFs se generan manualmente con Chrome headless apuntando al HTML del deck (proceso
  documentado en el README, no hay pipeline automático de generación).

## 7. Convención de íconos

- Se usan **solo como imágenes ilustrativas por diapositiva** (nunca como sprite/librería
  global cargada en el sitio).
- Fuente: [Simple Icons](https://github.com/simple-icons/simple-icons) para logos de marca
  (Java, GitHub, Zoom, Selenium, SonarCloud, etc.) o
  [Font Awesome Free](https://github.com/FortAwesome/Font-Awesome) para conceptos
  genéricos (bug, reloj, balanza, etc.).
- Se descargan como SVG y se recolorean manualmente (`fill="#59a87d"`) porque un `<img>`
  no hereda `currentColor`.
- Se guardan localmente en `presentaciones/<slug>/img/`, **no** en `assets/img/` — cada
  deck es dueño de sus propios íconos.
- Los íconos de la barra de navegación (compartir, breadcrumb, Gmail, LinkedIn) sí van
  inline como `<svg fill="currentColor">` en el HTML, para heredar color vía CSS.

## 9. SEO / Open Graph

Las 12 páginas del sitio (home, perfil, 4 índices de curso, 6 decks con contenido) incluyen
en el `<head>`: `description`, `canonical`, `og:*` y `twitter:*`, todas apuntando a
`assets/img/og-image.png` y a URLs absolutas bajo `https://profejuanfe.dev/`.

## 10. Botón "Compartir"

`assets/js/share.js` usa `navigator.share()` cuando está disponible (móviles, Safari,
Edge); si no, copia el link al portapapeles y muestra "¡Enlace copiado!" un par de
segundos. Presente en: home, cada índice de curso, perfil, y cada deck (junto a "Pantalla
completa"/"Descargar PDF").

## 12. Cómo agregar contenido nuevo (flujo documentado en el README)

1. Copiar una presentación existente como plantilla.
2. Escribir el contenido de cada `<section class="slide">`.
3. Agregar imagen ilustrativa solo si el slide tiene poco texto, siempre debajo del texto.
4. Agregar la entrada correspondiente en `topics.js` del curso con `available: true`.
5. Generar el PDF con Chrome headless y colocarlo en `<curso>/pdfs/<slug>.pdf`.

## 13. Notas / puntos de atención

- No hay hoja de estilos global de componentes: cambios de layout compartido implican
  editar cada CSS de página (`home.css`, `course.css`, `profile.css`) por separado; solo
  colores/tokens están centralizados en `variables.css`.
- El dominio `profejuanfe.dev` está hardcodeado como URL absoluta en las 12 páginas para
  SEO/Open Graph — si cambia, requiere find-and-replace across-the-board (señalado también
  como pendiente de confirmar en el propio README).
- No hay tests, linting ni pipeline de build — el despliegue es "subir tal cual" a Azure
  Static Web Apps.
- `staticwebapp.config.json` es mínimo (solo cache-control); no hay reglas de rutas,
  autenticación ni fallback SPA — no aplica porque el sitio es multi-página estático puro.
