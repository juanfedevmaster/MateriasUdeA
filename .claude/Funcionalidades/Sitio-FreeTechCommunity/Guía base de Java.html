Antes de empezar

Si terminas esta guía antes del 15 de diciembre, vas a llegar a la primera clase leyendo y escribiendo clases, interfaces y colecciones en Java sin trabarte. Es para ti si nunca has programado en Java o si te ubicaste en el nivel 1 del formulario de inscripción.

La semana 1 del curso va rápido y da por hecho que ya manejas lo que hay aquí. No necesitas saber de Spring Boot: la sección 14 te muestra cómo se conecta todo lo que aprendiste con lo que veremos en clase.

Lo que necesitas instalado

  • Java 21 (JDK) y Visual Studio Code con el Extension Pack for Java. Si aún no los tienes, sigue primero el Manual de instalación del curso.
  • Una carpeta de trabajo, por ejemplo java-base, donde guardes cada ejercicio.

Cómo usar la guía

  1. Escribe cada ejemplo a mano en lugar de copiarlo. Equivocarte con un punto y coma te enseña más que pegar el código.
  2. Ejecuta cada ejemplo y cambia algo para ver qué pasa.
  3. Al terminar cada tema haz sus ejercicios de la sección 15, y al final el proyecto integrador.
  4. Marca cada sección como estudiada con el botón de su encabezado. Tu avance se guarda en este navegador.
  5. Si te atascas más de 20 minutos, pregunta en el Discord de FreeTech Community con el código y el error completo.

1. Cómo funciona Java

Java es un lenguaje compilado a bytecode: escribes un archivo .java, el compilador lo convierte en un archivo .class y la JVM lo ejecuta en cualquier sistema operativo. Por eso se dice "escribe una vez, ejecuta en cualquier parte".

WindowsmacOSLinux
Pieza Qué es Para qué la usas
JDK (Java Development Kit) Kit completo: compilador, JVM, bibliotecas y herramientas Programar. Es lo que instalaste
JRE (Java Runtime Environment) Solo lo necesario para ejecutar Correr programas ya compilados

Tu primer programa

Crea un archivo llamado HolaMundo.java con este contenido:

public class HolaMundo {
    public static void main(String[] args) {
        System.out.println("Hola, FreeTech Community");
    }
}

Línea por línea:

  • public class HolaMundo: todo código en Java vive dentro de una clase. El nombre de la clase pública debe ser igual al nombre del archivo, con mayúsculas y minúsculas.
  • public static void main(String[] args): el punto de entrada. La JVM busca exactamente este método para arrancar el programa.
  • System.out.println(...): imprime un texto en la consola y salta de línea. System.out.print(...) imprime sin saltar.
  • Cada instrucción termina en ; y los bloques se delimitan con llaves { }.

Compilar y ejecutar desde la terminal

javac HolaMundo.java   # genera HolaMundo.class
java HolaMundo         # ejecuta la clase (sin la extensión)

Desde Java 11 también puedes ejecutar un archivo sin compilarlo antes: java HolaMundo.java. Es cómodo para pruebas rápidas.

Ejecutar en VS Code

Abre la carpeta del ejercicio en VS Code. Encima del método main aparecen los enlaces Run y Debug: haz clic en Run y el resultado sale en la terminal integrada. Con Debug puedes poner puntos de interrupción (clic a la izquierda del número de línea) y avanzar paso a paso para ver cómo cambian las variables.

Probar código suelto con jshell

jshell viene con el JDK y te deja probar líneas sin crear clases. Escribe jshell en la terminal y prueba:

jshell> int a = 5 * 3
a ==> 15
jshell> "java".toUpperCase()
$2 ==> "JAVA"
jshell> /exit

Reglas que debes recordar desde ya. Java distingue mayúsculas de minúsculas: Main, main y MAIN son tres cosas distintas. Un archivo .java puede tener varias clases, pero solo una pública, y esa da el nombre al archivo. Java es de tipado estático: cada variable tiene un tipo fijo que el compilador revisa antes de ejecutar, así que muchos errores aparecen al compilar y no en producción.

2. Sintaxis básica

En Java cada variable se declara con un tipo y ese tipo no cambia. Los tipos se dividen en primitivos (valores simples) y referencias (objetos como String).

Variables

int edad = 20;              // tipo, nombre, valor
double precio = 49_900.50;  // el guion bajo solo mejora la lectura
boolean activo = true;
char inicial = 'J';         // un carácter va entre comillas simples
String nombre = "Ana";      // un texto va entre comillas dobles

edad = 21;                  // reasignar: ya no se escribe el tipo

String no es primitivo: es una clase. Por eso empieza con mayúscula y tiene métodos como nombre.length().

Dinero y decimales. No uses double para dinero real, porque acumula errores de redondeo: 0.1 + 0.2 da 0.30000000000000004. En la industria se usa BigDecimal, que veremos en el curso.

Inferencia de tipos con var

Dentro de un método puedes dejar que el compilador deduzca el tipo. La variable sigue teniendo un tipo fijo; solo te ahorras escribirlo.

var ciudad = "Medellín";   // String
var total = 0;             // int
// ciudad = 10;            // error: ciudad es String

Constantes

final impide reasignar. Por convención las constantes se escriben en mayúsculas.

final double IVA = 0.19;
final int MAX_INTENTOS = 3;

Operadores

Los operadores lógicos combinan condiciones: && (Y, las dos deben cumplirse), || (O, basta una) y ! (NO, invierte). Por ejemplo activo && edad >= 18.

Ojo con la división: si los dos operandos son enteros, el resultado es entero. 7 / 2 da 3; para obtener 3.5 escribe 7 / 2.0 o (double) 7 / 2.

Leer datos del usuario y mostrar resultados

import java.util.Scanner;

public class Saludo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("¿Cómo te llamas? ");
        String nombre = sc.nextLine();

        System.out.print("¿Cuántos años tienes? ");
        int edad = sc.nextInt();

        System.out.printf("Hola %s, el próximo año tendrás %d años%n", nombre, edad + 1);
        sc.close();
    }
}

En printf: %s es texto, %d entero, %.2f decimal con 2 cifras y %n salto de línea.

Trampa de Scanner. Si llamas nextLine() justo después de nextInt(), lee el salto de línea pendiente y te devuelve un texto vacío. Agrega un sc.nextLine() extra para limpiarlo.

3. Control de flujo

Con condicionales decides qué código se ejecuta y con ciclos lo repites. Las condiciones siempre deben dar un boolean.

if, else if, else

double nota = 3.8;

if (nota >= 4.5) {
    System.out.println("Excelente");
} else if (nota >= 3.0) {
    System.out.println("Aprobado");
} else {
    System.out.println("Reprobado");
}

Usa siempre llaves, aunque el bloque tenga una sola línea. Evitas errores cuando alguien agrega una segunda línea después.

Operador ternario

Un if corto que devuelve un valor: condición ? siEsVerdad : siEsFalso.

String estado = nota >= 3.0 ? "Aprobado" : "Reprobado";

switch moderno

Desde Java 14 el switch puede devolver un valor y usa flechas ->, sin necesidad de break.

int dia = 3;

String nombreDia = switch (dia) {
    case 1 -> "Lunes";
    case 2 -> "Martes";
    case 3 -> "Miércoles";
    case 4 -> "Jueves";
    case 5 -> "Viernes";
    case 6, 7 -> "Fin de semana";
    default -> "Día inválido";
};

Si un caso necesita varias líneas, usa un bloque y devuelve el valor con yield:

double descuento = switch (tipoCliente) {
    case "VIP" -> 0.20;
    case "FRECUENTE" -> {
        System.out.println("Cliente frecuente");
        yield 0.10;
    }
    default -> 0.0;
};

Vas a encontrar el switch antiguo con case 1: y break; en código viejo. Funciona, pero si olvidas un break el programa sigue ejecutando el caso siguiente. Prefiere el de flechas.

while y do-while

while revisa la condición antes de cada vuelta; do-while ejecuta al menos una vez.

int intentos = 0;
while (intentos < 3) {
    System.out.println("Intento " + (intentos + 1));
    intentos++;
}

int opcion;
do {
    System.out.println("1. Listar  2. Agregar  0. Salir");
    opcion = sc.nextInt();
} while (opcion != 0);

Si la condición nunca se vuelve falsa tienes un ciclo infinito. Detén el programa con Ctrl+C en la terminal o con el botón de detener en VS Code.

for

Cuando sabes cuántas veces repetir: inicio, condición y paso.

for (int i = 1; i <= 5; i++) {
    System.out.println("5 x " + i + " = " + (5 * i));
}

for-each

Para recorrer todos los elementos de un arreglo o una colección sin manejar índices. Es el que más vas a usar.

String[] lenguajes = {"Java", "Python", "C#"};

for (String lenguaje : lenguajes) {
    System.out.println(lenguaje);
}

break y continue

break sale del ciclo inmediatamente; continue salta a la siguiente vuelta.

for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) continue;   // ignora los pares
    if (i > 7) break;           // termina al pasar de 7
    System.out.println(i);      // imprime 1, 3, 5, 7
}

4. Arreglos y cadenas

Un arreglo guarda una cantidad fija de valores del mismo tipo; un String es una cadena de texto que no se puede modificar. En el día a día usarás más las colecciones de la sección 10, pero los arreglos son la base.

Arreglos

int[] notas = new int[5];                 // 5 posiciones, todas en 0
notas[0] = 4;                             // los índices empiezan en 0
notas[4] = 5;                             // la última posición es length - 1

String[] dias = {"Lun", "Mar", "Mié"};    // declarar e inicializar
System.out.println(dias.length);          // 3 (length es un atributo, sin paréntesis)

// notas[5] = 3;   // ArrayIndexOutOfBoundsException: no existe la posición 5

Recorrer un arreglo:

int suma = 0;
for (int nota : notas) {
    suma += nota;
}
double promedio = (double) suma / notas.length;

La clase Arrays tiene utilidades listas:

import java.util.Arrays;

int[] numeros = {5, 2, 9, 1};
Arrays.sort(numeros);                          // ordena: [1, 2, 5, 9]
System.out.println(Arrays.toString(numeros));  // imprime "[1, 2, 5, 9]"

Si imprimes un arreglo directamente (System.out.println(numeros)) ves algo como [I@1b6d3586, que es su identificador en memoria. Usa Arrays.toString.

Matrices

Un arreglo de arreglos:

int[][] tablero = {
    {1, 2, 3},
    {4, 5, 6}
};
System.out.println(tablero[1][2]);   // 6: fila 1, columna 2

for (int[] fila : tablero) {
    for (int celda : fila) {
        System.out.print(celda + " ");
    }
    System.out.println();
}

Cadenas (String)

Un String es inmutable: sus métodos no lo cambian, devuelven uno nuevo. Por eso nombre.trim(); sola no hace nada; debes guardar el resultado.

String nombre = "  Juan Felipe  ";
nombre.trim();                 // no cambia nombre
nombre = nombre.trim();        // ahora sí: "Juan Felipe"

Compara textos con equals, nunca con ==

== compara si dos variables apuntan al mismo objeto en memoria, no si tienen el mismo texto. Es uno de los errores más comunes al empezar.

String a = "java";
String b = new String("java");

System.out.println(a == b);        // false: son objetos distintos
System.out.println(a.equals(b));   // true: mismo contenido

Si el valor puede ser null, pon primero el texto conocido: "ADMIN".equals(rol) no falla aunque rol sea null.

StringBuilder

Concatenar con + dentro de un ciclo crea muchos objetos intermedios. StringBuilder arma el texto en un solo objeto modificable.

StringBuilder sb = new StringBuilder();
for (int i = 1; i <= 3; i++) {
    sb.append("Fila ").append(i).append("\n");
}
String resultado = sb.toString();

Text blocks y formato

Desde Java 15 puedes escribir texto de varias líneas con triple comilla. Es muy útil para JSON y SQL, que verás en el curso.

String json = """
    {
      "nombre": "Teclado",
      "precio": 120000
    }
    """;

String mensaje = "Hola %s, tienes %d mensajes".formatted("Ana", 3);

5. Métodos

Un método es un bloque de código con nombre que recibe datos, hace una tarea y opcionalmente devuelve un resultado. Dividir el programa en métodos pequeños, de una sola responsabilidad, es lo que hace legible el código.

Anatomía de un método

public static double calcularPrecioConIva(double precio, double iva) {
    return precio * (1 + iva);
}
Parte En el ejemplo Significado
Modificador de acceso public Quién puede llamarlo (sección 6)
static static Pertenece a la clase, no a un objeto
Tipo de retorno double Qué devuelve; void si no devuelve nada
Nombre calcularPrecioConIva Un verbo en camelCase
Parámetros (double precio, double iva) Datos de entrada, cada uno con su tipo
Cuerpo { return ...; } Lo que hace

La combinación de nombre y tipos de parámetros se llama firma.

Llamar métodos

public class Calculadora {

    public static void main(String[] args) {
        double total = calcularPrecioConIva(100_000, 0.19);
        imprimirLinea("Total: " + total);
    }

    static double calcularPrecioConIva(double precio, double iva) {
        return precio * (1 + iva);
    }

    static void imprimirLinea(String texto) {   // void: no devuelve nada
        System.out.println("> " + texto);
    }
}

Si el método declara un tipo de retorno, todos los caminos deben terminar en return. Si no, el compilador muestra missing return statement.

Sobrecarga

Varios métodos pueden llamarse igual si sus parámetros son distintos. Java elige cuál usar según los argumentos.

static int sumar(int a, int b) { return a + b; }
static int sumar(int a, int b, int c) { return a + b + c; }
static double sumar(double a, double b) { return a + b; }

sumar(2, 3);        // usa el primero
sumar(2, 3, 4);     // usa el segundo
sumar(2.5, 1.5);    // usa el tercero

Parámetros variables (varargs)

static double promedio(double... valores) {   // valores es un arreglo
    double suma = 0;
    for (double v : valores) suma += v;
    return valores.length == 0 ? 0 : suma / valores.length;
}

promedio(4.0, 3.5, 5.0);

Java pasa todo por valor

Cuando llamas un método, Java le entrega una copia de cada argumento.

  • Con primitivos se copia el valor: cambiarlo dentro del método no afecta la variable original.
  • Con objetos se copia la referencia: el método apunta al mismo objeto, así que sí puede modificar su contenido.
static void duplicar(int x) { x = x * 2; }
static void cambiarPrimero(int[] arr) { arr[0] = 99; }

int n = 5;
duplicar(n);            // n sigue en 5

int[] datos = {1, 2};
cambiarPrimero(datos);  // datos[0] ahora es 99

Alcance de las variables

Una variable existe solo dentro del bloque { } donde se declaró.

for (int i = 0; i < 3; i++) {
    int doble = i * 2;
}
// System.out.println(doble);   // error: doble no existe aquí

static o no static

Hasta ahora todos los métodos son static porque los llamamos desde main sin crear objetos. En la siguiente sección verás métodos de instancia, que trabajan con los datos de cada objeto. Regla práctica: en una aplicación Spring Boot casi nada es static, salvo constantes y utilidades.

6. Clases y objetos

Una clase es un molde que define qué datos tiene algo (atributos) y qué sabe hacer (métodos); un objeto es una instancia concreta creada con ese molde. Todo en Spring Boot gira alrededor de clases: controladores, servicios, entidades y DTO.

Tu primera clase

public class Producto {

    // Atributos: el estado de cada objeto
    private String nombre;
    private double precio;
    private int stock;

    // Constructor: se ejecuta al crear el objeto con new
    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }

    // Métodos de instancia: trabajan con los datos de ESTE objeto
    public boolean hayDisponible() {
        return stock > 0;
    }

    public void vender(int cantidad) {
        stock -= cantidad;
    }
}

Crear y usar objetos:

Producto teclado = new Producto("Teclado", 120_000, 10);
Producto mouse = new Producto("Mouse", 45_000, 0);

teclado.vender(2);
System.out.println(teclado.hayDisponible());   // true
System.out.println(mouse.hayDisponible());     // false

Cada objeto tiene sus propios atributos: vender teclados no cambia el stock del mouse.

this

this se refiere al objeto actual. En el constructor, this.nombre = nombre significa "asigna al atributo nombre de este objeto el parámetro nombre". Sin this, el parámetro tapa al atributo y la asignación no hace nada.

Varios constructores

public Producto(String nombre, double precio) {
    this(nombre, precio, 0);   // llama al otro constructor con stock en 0
}

Si no escribes ningún constructor, Java crea uno vacío sin parámetros. Si escribes al menos uno, ese constructor vacío deja de existir, a menos que lo declares tú.

Encapsulamiento: getters y setters

Los atributos son private para que nadie los cambie sin control. El acceso se hace con métodos que pueden validar.

public String getNombre() {
    return nombre;
}

public double getPrecio() {
    return precio;
}

public void setPrecio(double precio) {
    if (precio < 0) {
        throw new IllegalArgumentException("El precio no puede ser negativo");
    }
    this.precio = precio;
}

No crees un setter para todo por costumbre. Si un dato no debe cambiar después de crear el objeto, decláralo final y no le pongas setter. VS Code genera getters, setters y constructores: clic derecho, Source Action.

toString, equals y hashCode

Toda clase hereda estos tres métodos de Object. Casi siempre conviene sobrescribirlos.

import java.util.Objects;

@Override
public String toString() {
    return "Producto{nombre='" + nombre + "', precio=" + precio + ", stock=" + stock + "}";
}

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Producto otro)) return false;
    return Objects.equals(nombre, otro.nombre);
}

@Override
public int hashCode() {
    return Objects.hash(nombre);
}
  • toString() define cómo se ve el objeto al imprimirlo. Sin él verás algo como Producto@4e25154f.
  • equals() define cuándo dos objetos son iguales por contenido. Sin él, solo son iguales si son el mismo objeto en memoria.
  • hashCode() debe ser coherente con equals(): si dos objetos son iguales, deben tener el mismo hash. Si no, HashSet y HashMap funcionan mal.

Miembros static

Un atributo static es compartido por todos los objetos de la clase.

public class Producto {
    private static int totalCreados = 0;   // uno solo para toda la clase

    public Producto(String nombre, double precio, int stock) {
        // ...
        totalCreados++;
    }

    public static int getTotalCreados() {
        return totalCreados;
    }
}

Producto.getTotalCreados();   // se llama con el nombre de la clase

Paquetes e imports

Los paquetes organizan las clases en carpetas y evitan choques de nombres. La declaración package debe coincidir con la carpeta.

// archivo: src/main/java/com/freetech/tienda/modelo/Producto.java
package com.freetech.tienda.modelo;

import java.util.List;                       // clase de la biblioteca estándar
import com.freetech.tienda.util.Formatos;    // clase de otro paquete tuyo

Las clases de java.lang (String, Math, Integer, System) se importan solas.

Modificadores de acceso

Modificador Visible desde Uso típico
public Cualquier clase Clases y métodos que otros deben usar
protected El mismo paquete y las subclases Métodos pensados para herencia
Sin modificador (de paquete) Solo el mismo paquete Clases auxiliares internas
private Solo la propia clase Atributos y métodos internos

Regla general: empieza con private y abre solo lo necesario.

Referencias y null

Una variable de tipo objeto no guarda el objeto: guarda una referencia a él. Si no apunta a nada, vale null.

Producto p1 = new Producto("Monitor", 800_000, 3);
Producto p2 = p1;          // p2 apunta al MISMO objeto
p2.vender(1);              // p1 también ve stock = 2

Producto p3 = null;
// p3.vender(1);           // NullPointerException: no hay objeto

El error más frecuente. NullPointerException aparece cuando usas una variable que vale null. Verifica null antes de usar un objeto que puede no existir, o usa Optional (sección 10).

7. Herencia y polimorfismo

La herencia permite que una clase hija reutilice y especialice a una clase padre; el polimorfismo permite tratar objetos distintos de la misma forma y que cada uno responda a su manera. Java solo permite heredar de una clase.

extends y super

public class Empleado {
    protected String nombre;
    protected double salarioBase;

    public Empleado(String nombre, double salarioBase) {
        this.nombre = nombre;
        this.salarioBase = salarioBase;
    }

    public double calcularPago() {
        return salarioBase;
    }
}

public class Gerente extends Empleado {
    private double bono;

    public Gerente(String nombre, double salarioBase, double bono) {
        super(nombre, salarioBase);   // llama al constructor del padre, siempre primero
        this.bono = bono;
    }

    @Override
    public double calcularPago() {
        return super.calcularPago() + bono;   // reutiliza la lógica del padre
    }
}

Cada clase pública va en su propio archivo: Empleado.java y Gerente.java. Aplica igual para todos los ejemplos de esta guía que muestran varias clases juntas.

  • extends indica de quién hereda. Gerente tiene todo lo de Empleado más lo suyo.
  • super(...) llama al constructor del padre. super.metodo() llama a la versión del padre.
  • @Override le dice al compilador que estás sobrescribiendo un método. Si te equivocas en el nombre o los parámetros, te avisa con un error. Úsalo siempre.

Polimorfismo

Una variable del tipo padre puede guardar cualquier hijo. Al llamar un método, se ejecuta la versión del objeto real.

Empleado[] equipo = {
    new Empleado("Ana", 3_000_000),
    new Gerente("Luis", 5_000_000, 1_500_000)
};

double nomina = 0;
for (Empleado e : equipo) {
    nomina += e.calcularPago();   // Ana: 3.000.000, Luis: 6.500.000
}

El ciclo no sabe ni le importa qué tipo de empleado es cada uno. Si mañana agregas Practicante, el ciclo sigue funcionando sin cambios.

Clases abstractas

Una clase abstract no se puede instanciar: existe para ser heredada. Sus métodos abstract no tienen cuerpo y obligan a cada hija a implementarlos.

public abstract class Figura {
    public abstract double area();

    public String describir() {          // también puede tener métodos normales
        return "Figura de área " + area();
    }
}

public class Circulo extends Figura {
    private final double radio;
    public Circulo(double radio) { this.radio = radio; }

    @Override
    public double area() { return Math.PI * radio * radio; }
}

public class Rectangulo extends Figura {
    private final double base, altura;
    public Rectangulo(double base, double altura) { this.base = base; this.altura = altura; }

    @Override
    public double area() { return base * altura; }
}

// Figura f = new Figura();   // error: es abstracta
Figura f = new Circulo(2);     // válido

instanceof con patrón

Para preguntar el tipo real de un objeto y usarlo en la misma línea (Java 16 o superior):

if (f instanceof Circulo c) {
    System.out.println("Es un círculo de área " + c.area());
}

Si te descubres llenando el código de instanceof, casi siempre falta un método polimórfico en la clase padre.

La clase Object y final

  • Toda clase hereda de Object aunque no lo escribas. De ahí vienen toString(), equals() y hashCode().
  • Una clase final no puede tener hijas. String es final.
  • Un método final no se puede sobrescribir.

Composición antes que herencia

Hereda solo cuando la relación es "es un": un Gerente es un Empleado. Cuando la relación es "tiene un", usa un atributo: un Pedido tiene una lista de productos, no hereda de Producto.

public class Pedido {
    private Cliente cliente;          // composición: Pedido TIENE un Cliente
    private Producto[] productos;
}

Las jerarquías profundas de herencia son difíciles de mantener. En Spring Boot casi no verás herencia entre tus clases; verás mucha composición e interfaces.

8. Interfaces

Una interfaz es un contrato: dice qué métodos debe tener una clase, sin decir cómo se implementan. Es el concepto más importante de esta guía para Spring Boot, porque Spring está construido sobre "programar contra interfaces".

Definir e implementar

public interface Notificador {
    void enviar(String destino, String mensaje);   // público y abstracto por defecto
}

public class NotificadorEmail implements Notificador {
    @Override
    public void enviar(String destino, String mensaje) {
        System.out.println("Email a " + destino + ": " + mensaje);
    }
}

public class NotificadorSms implements Notificador {
    @Override
    public void enviar(String destino, String mensaje) {
        System.out.println("SMS a " + destino + ": " + mensaje);
    }
}

Una clase que hace implements está obligada a escribir todos los métodos de la interfaz. Si falta uno, no compila.

Programar contra la interfaz

La clase que usa el notificador no sabe cuál implementación recibe. Solo conoce el contrato.

public class ServicioPedidos {

    private final Notificador notificador;   // depende de la interfaz, no de una clase concreta

    public ServicioPedidos(Notificador notificador) {
        this.notificador = notificador;      // alguien de afuera le entrega la implementación
    }

    public void confirmarPedido(String cliente) {
        // ... lógica del pedido
        notificador.enviar(cliente, "Tu pedido fue confirmado");
    }
}

// Hoy por email
ServicioPedidos servicio = new ServicioPedidos(new NotificadorEmail());

// Mañana por SMS, sin tocar una línea de ServicioPedidos
ServicioPedidos otro = new ServicioPedidos(new NotificadorSms());

Esto se llama inyección de dependencias: la clase no crea lo que necesita con new, se lo entregan por el constructor. Ventajas:

  • Cambias la implementación sin modificar la clase que la usa.
  • En las pruebas le pasas una implementación falsa que no envía emails reales.
  • Cada clase tiene una sola responsabilidad.

Por qué importa para el curso. En Spring Boot no escribes esos new: Spring crea los objetos y los inyecta por ti. Si entiendes este ejemplo, entiendes la idea central de Spring.

Varias interfaces a la vez

Una clase hereda de una sola clase, pero puede implementar muchas interfaces.

public interface Exportable { String exportarCsv(); }
public interface Auditable { String getUsuarioCreador(); }

public class Factura implements Exportable, Auditable {
    @Override public String exportarCsv() { return "..."; }
    @Override public String getUsuarioCreador() { return "admin"; }
}

Métodos default y static

Desde Java 8 una interfaz puede traer métodos con cuerpo. Las clases los heredan y pueden sobrescribirlos.

public interface Notificador {
    void enviar(String destino, String mensaje);

    default void enviarATodos(String[] destinos, String mensaje) {
        for (String d : destinos) {
            enviar(d, mensaje);
        }
    }

    static boolean esDestinoValido(String destino) {
        return destino != null && !destino.isBlank();
    }
}

Las interfaces también pueden tener constantes, pero no atributos de instancia.

Interfaz o clase abstracta

Interfaz Clase abstracta
Cuántas puede usar una clase Varias (implements A, B) Solo una (extends A)
Atributos de instancia No, solo constantes Sí
Constructores No Sí
Cuándo usarla Definir una capacidad o contrato Compartir estado y código entre clases muy parecidas

En la duda, empieza con una interfaz.

Interfaces que verás en el curso

  • List, Set y Map son interfaces; ArrayList y HashMap son implementaciones (sección 10).
  • Comparable y Comparator definen cómo ordenar objetos.
  • JpaRepository de Spring Data es una interfaz que tú declaras y Spring implementa automáticamente para hablar con PostgreSQL.

9. Records y enums

Un record es una clase inmutable para transportar datos, escrita en una línea; un enum es un tipo con un conjunto cerrado de valores. Los dos aparecen en todas las APIs que construiremos.

Records

Antes de Java 16, una clase para llevar datos necesitaba atributos, constructor, getters, equals, hashCode y toString. Un record genera todo eso por ti:

public record ProductoDto(String nombre, double precio, int stock) { }

ProductoDto dto = new ProductoDto("Teclado", 120_000, 10);

System.out.println(dto.nombre());   // los accesores se llaman igual que el campo, sin "get"
System.out.println(dto);            // ProductoDto[nombre=Teclado, precio=120000.0, stock=10]

ProductoDto otro = new ProductoDto("Teclado", 120_000, 10);
System.out.println(dto.equals(otro));   // true: compara por contenido

Características:

  • Sus campos son private final: no hay setters y no se pueden cambiar.
  • Puede tener métodos propios y métodos static.
  • No puede heredar de otra clase, pero sí implementar interfaces.

Validar en el constructor compacto:

public record ProductoDto(String nombre, double precio, int stock) {
    public ProductoDto {
        if (nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("El nombre es obligatorio");
        }
        if (precio < 0) {
            throw new IllegalArgumentException("El precio no puede ser negativo");
        }
    }

    public double valorInventario() {
        return precio * stock;
    }
}

Dónde los verás. En el curso usaremos records como DTO (Data Transfer Object): los objetos que una API recibe y devuelve en JSON. Spring convierte un record a JSON y de JSON a record sin que escribas nada.

Enums

Cuando una variable solo puede tomar ciertos valores, un enum evita errores de escritura como "ENVIADO" contra "Enviado".

public enum EstadoPedido {
    PENDIENTE, PAGADO, ENVIADO, ENTREGADO, CANCELADO
}

EstadoPedido estado = EstadoPedido.PAGADO;

if (estado == EstadoPedido.PAGADO) {          // los enums sí se comparan con ==
    System.out.println("Listo para enviar");
}

String mensaje = switch (estado) {
    case PENDIENTE -> "Esperando pago";
    case PAGADO -> "Preparando tu pedido";
    case ENVIADO -> "En camino";
    case ENTREGADO -> "Entregado";
    case CANCELADO -> "Cancelado";
};   // el compilador sabe que cubriste todos los casos, no necesitas default

Métodos útiles:

EstadoPedido.values();                 // arreglo con todos los valores
EstadoPedido.valueOf("ENVIADO");       // de texto a enum (falla si no existe)
estado.name();                         // de enum a texto: "PAGADO"
estado.ordinal();                      // posición: 1 (evita depender de esto)

Enums con atributos y métodos

Un enum es una clase especial: puede tener atributos, constructor y métodos.

public enum Plan {
    BASICO(0), PRO(49_900), EMPRESARIAL(199_900);

    private final int precioMensual;

    Plan(int precioMensual) {          // el constructor de un enum siempre es privado
        this.precioMensual = precioMensual;
    }

    public int getPrecioMensual() {
        return precioMensual;
    }

    public boolean esGratis() {
        return precioMensual == 0;
    }
}

Plan.PRO.getPrecioMensual();   // 49900

10. Genéricos y colecciones

Las colecciones son estructuras que crecen y se encogen según lo necesites; los genéricos (<Tipo>) le dicen al compilador qué guardan. En una API casi todo lo que recibes y devuelves son listas y mapas de objetos.

Todas viven en el paquete java.util. Si VS Code marca un error en List, Map o Comparator, pon el cursor encima y presiona Ctrl+. para agregar el import.

Genéricos y clases envoltorio

List<String> nombres = new ArrayList<>();   // lista que solo acepta String
nombres.add("Ana");
// nombres.add(25);                          // error al compilar: 25 no es String
String primero = nombres.get(0);             // no necesitas hacer cast

El <> vacío a la derecha se llama operador diamante: el compilador repite el tipo de la izquierda.

Las colecciones solo guardan objetos, no primitivos. Para eso existen las clases envoltorio, y Java convierte entre ellas automáticamente (autoboxing):

Primitivo Envoltorio
int Integer
long Long
double Double
boolean Boolean
char Character 
List<Integer> edades = new ArrayList<>();   // List<int> no compila
edades.add(20);                             // el int 20 se convierte en Integer
int primera = edades.get(0);                // y de vuelta a int

Un Integer puede ser null y un int no. Si conviertes un Integer nulo a int, obtienes NullPointerException.

List: ordenada y con duplicados

import java.util.ArrayList;
import java.util.List;

List<String> tareas = new ArrayList<>();
tareas.add("Instalar Java");          // agrega al final
tareas.add("Leer la guía");
tareas.add(0, "Crear carpeta");       // agrega en la posición 0

tareas.get(1);                        // "Instalar Java"
tareas.set(1, "Instalar JDK 21");     // reemplaza
tareas.remove("Leer la guía");        // elimina por valor
tareas.size();                        // 2
tareas.contains("Crear carpeta");     // true
tareas.isEmpty();                     // false
tareas.indexOf("Instalar JDK 21");    // 1

for (String t : tareas) {
    System.out.println(t);
}

Declara la variable con la interfaz (List) y crea la implementación (ArrayList). Así puedes cambiar de implementación sin tocar el resto del código, igual que en la sección 8.

Set: sin duplicados

import java.util.HashSet;
import java.util.Set;

Set<String> correos = new HashSet<>();
correos.add("ana@mail.com");
correos.add("luis@mail.com");
boolean agregado = correos.add("ana@mail.com");   // false: ya estaba

correos.size();                     // 2
correos.contains("luis@mail.com");  // true, y muy rápido aunque haya millones

HashSet no garantiza ningún orden. LinkedHashSet respeta el orden de inserción y TreeSet los mantiene ordenados.

Para que un Set detecte duplicados de tus propias clases, la clase debe sobrescribir equals y hashCode (sección 6). Los records ya lo traen.

Map: pares clave y valor

import java.util.HashMap;
import java.util.Map;

Map<String, Integer> inventario = new HashMap<>();
inventario.put("Teclado", 10);
inventario.put("Mouse", 25);
inventario.put("Teclado", 8);                   // misma clave: reemplaza el valor

inventario.get("Mouse");                        // 25
inventario.get("Monitor");                      // null: no existe
inventario.getOrDefault("Monitor", 0);          // 0
inventario.containsKey("Teclado");              // true
inventario.remove("Mouse");

for (Map.Entry<String, Integer> e : inventario.entrySet()) {
    System.out.println(e.getKey() + ": " + e.getValue());
}

Contar ocurrencias es un uso clásico:

String[] votos = {"Java", "Python", "Java", "Go", "Java"};
Map<String, Integer> conteo = new HashMap<>();
for (String v : votos) {
    conteo.merge(v, 1, Integer::sum);   // si no existe pone 1, si existe suma 1
}
// {Java=3, Python=1, Go=1}

Cuál usar

Necesitas Usa Implementación habitual
Una secuencia en orden, con posiciones y duplicados List ArrayList
Elementos únicos o saber rápido si algo existe Set HashSet
Buscar un valor por una clave (id, correo, código) Map HashMap
Lo anterior pero conservando el orden de inserción LinkedHashSet o LinkedHashMap
Lo anterior pero siempre ordenado TreeSet o TreeMap

Colecciones inmutables

List<String> roles = List.of("ADMIN", "USER");
Set<Integer> primos = Set.of(2, 3, 5, 7);
Map<String, Integer> puertos = Map.of("http", 80, "https", 443);

// roles.add("GUEST");   // UnsupportedOperationException: no se puede modificar

Úsalas para datos fijos. Si necesitas una copia que sí se pueda modificar: new ArrayList<>(roles).

Ordenar

List<Integer> numeros = new ArrayList<>(List.of(5, 2, 9, 1));
Collections.sort(numeros);                   // [1, 2, 5, 9]
numeros.sort(Comparator.reverseOrder());     // [9, 5, 2, 1]

List<ProductoDto> productos = new ArrayList<>(/* ... */);
productos.sort(Comparator.comparing(ProductoDto::precio));            // por precio
productos.sort(Comparator.comparing(ProductoDto::nombre).reversed()); // por nombre, Z a A

ProductoDto::precio es una referencia a método; la explicamos en la sección 12.

Eliminar mientras recorres

Modificar una lista dentro de un for-each lanza ConcurrentModificationException. Usa removeIf:

// for (String t : tareas) { if (t.startsWith("X")) tareas.remove(t); }   // falla
tareas.removeIf(t -> t.startsWith("X"));                                   // correcto

Optional: un valor que puede no estar

Optional es una caja que tiene un valor o está vacía. Sirve para que un método diga claramente "puede que no encuentre nada" en lugar de devolver null.

import java.util.Optional;

Optional<ProductoDto> buscarPorNombre(List<ProductoDto> lista, String nombre) {
    for (ProductoDto p : lista) {
        if (p.nombre().equalsIgnoreCase(nombre)) {
            return Optional.of(p);
        }
    }
    return Optional.empty();
}

Optional<ProductoDto> resultado = buscarPorNombre(productos, "Teclado");

resultado.isPresent();                          // true si encontró algo
resultado.ifPresent(p -> System.out.println(p));
ProductoDto p = resultado.orElse(null);         // el valor o un reemplazo
ProductoDto q = resultado.orElseThrow(() -> new IllegalArgumentException("No existe"));

En Spring Data, repository.findById(id) devuelve un Optional. Lo usarás desde la semana 2.

11. Excepciones

Una excepción es un objeto que representa un error en tiempo de ejecución; si nadie la atrapa, el programa se detiene y muestra la traza del error. Manejarlas bien es lo que diferencia una API que responde "producto no encontrado" de una que se cae.

Leer una traza de error

Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Calculadora.dividir(Calculadora.java:12)
    at Calculadora.main(Calculadora.java:5)

Léela de arriba hacia abajo: el tipo de error (ArithmeticException), el mensaje (/ by zero) y la primera línea de tu código donde ocurrió (Calculadora.java:12). Esa línea es donde empiezas a buscar.

try, catch y finally

try {
    int numero = Integer.parseInt(textoUsuario);
    System.out.println("El doble es " + numero * 2);
} catch (NumberFormatException e) {
    System.out.println("Eso no es un número: " + e.getMessage());
} finally {
    System.out.println("Esto se ejecuta siempre, haya error o no");
}
  • try envuelve el código que puede fallar.
  • catch atrapa un tipo de excepción y decide qué hacer. Puede haber varios catch, del más específico al más general.
  • finally es opcional y se ejecuta siempre; sirve para liberar recursos.

Varios tipos en un solo catch:

catch (NumberFormatException | ArithmeticException e) { ... }

Jerarquía: checked y unchecked

Tipo Hereda de El compilador exige manejarla Ejemplos
Checked Exception Sí: o la atrapas o la declaras con throws IOException, SQLException
Unchecked RuntimeException No NullPointerException, IllegalArgumentException, NumberFormatException
Error Error No, y no debes atraparlos OutOfMemoryError, StackOverflowError

Las checked representan problemas externos que pueden pasar aunque tu código esté bien (un archivo que no existe). Las unchecked casi siempre son errores de programación o datos inválidos.

Lanzar excepciones con throw

public void retirar(double monto) {
    if (monto <= 0) {
        throw new IllegalArgumentException("El monto debe ser positivo");
    }
    if (monto > saldo) {
        throw new IllegalStateException("Saldo insuficiente");
    }
    saldo -= monto;
}

Valida al inicio del método y falla rápido con un mensaje claro.

Declarar con throws

Si un método puede lanzar una excepción checked y no quiere manejarla, la declara para que la maneje quien lo llama:

public String leerArchivo(String ruta) throws IOException {
    return Files.readString(Path.of(ruta));
}

Tus propias excepciones

public class ProductoNoEncontradoException extends RuntimeException {
    public ProductoNoEncontradoException(Long id) {
        super("No existe un producto con id " + id);
    }
}

// uso
throw new ProductoNoEncontradoException(15L);

Hereda de RuntimeException para que sea unchecked. Un nombre específico dice mucho más que una excepción genérica.

try-with-resources

Los recursos que hay que cerrar (archivos, conexiones, Scanner) se declaran entre paréntesis y Java los cierra solo, aunque haya error:

try (Scanner sc = new Scanner(Path.of("datos.txt"))) {
    while (sc.hasNextLine()) {
        System.out.println(sc.nextLine());
    }
} catch (IOException e) {
    System.out.println("No se pudo leer el archivo: " + e.getMessage());
}

Buenas prácticas

  • Nunca dejes un catch vacío: escondes el error y luego nadie sabe qué pasó.
  • Atrapa la excepción más específica posible, no Exception en todas partes.
  • No uses excepciones para el flujo normal del programa; úsalas para situaciones excepcionales.
  • Escribe mensajes que ayuden a quien lee el error: qué falló y con qué dato.

En Spring Boot. Lanzarás ProductoNoEncontradoException desde un servicio y un manejador global con @ExceptionHandler la convertirá en una respuesta HTTP 404. Lo verás en clase.

12. Lambdas y Streams

Una lambda es una función corta que puedes pasar como valor; los streams usan lambdas para filtrar, transformar y resumir colecciones en pocas líneas. El código moderno de Java y de Spring está lleno de ambos. Los collectors se importan desde java.util.stream.Collectors.

Interfaces funcionales y lambdas

Una interfaz funcional tiene un solo método abstracto. Una lambda es una forma corta de implementarla sin crear una clase.

// Con una clase anónima (forma antigua)
Comparator<String> porLargo = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return Integer.compare(a.length(), b.length());
    }
};

// Con una lambda: lo mismo en una línea
Comparator<String> porLargoLambda = (a, b) -> Integer.compare(a.length(), b.length());

Sintaxis: (parámetros) -> expresión o (parámetros) -> { bloque con return; }. Si hay un solo parámetro, los paréntesis son opcionales: x -> x * 2.

Las interfaces funcionales que más usarás vienen en java.util.function:

Interfaz Recibe Devuelve Ejemplo
Predicate<T> Un T boolean p -> p.precio() > 100_000
Function<T, R> Un T Un R p -> p.nombre()
Consumer<T> Un T Nada p -> System.out.println(p)
Supplier<T> Nada Un T () -> new ArrayList<>()

Referencias a métodos

Cuando la lambda solo llama un método existente, puedes escribirla más corta con ::.

Lambda Referencia a método
p -> p.nombre() ProductoDto::nombre
s -> System.out.println(s) System.out::println
s -> Integer.parseInt(s) Integer::parseInt
() -> new ArrayList<>() ArrayList::new

Streams

Un stream es una tubería: tomas una colección, le aplicas operaciones intermedias y terminas con una operación final que produce el resultado. El stream no modifica la colección original.

List<ProductoDto> productos = List.of(
    new ProductoDto("Teclado", 120_000, 10),
    new ProductoDto("Mouse", 45_000, 0),
    new ProductoDto("Monitor", 800_000, 3),
    new ProductoDto("Audífonos", 95_000, 7)
);

List<String> disponiblesCaros = productos.stream()
    .filter(p -> p.stock() > 0)                  // intermedia: conserva los que cumplen
    .filter(p -> p.precio() > 90_000)
    .sorted(Comparator.comparing(ProductoDto::precio))   // intermedia: ordena
    .map(ProductoDto::nombre)                    // intermedia: transforma cada elemento
    .toList();                                   // final: arma el resultado

// [Audífonos, Teclado, Monitor]

Operaciones que más usarás

Operación Tipo Qué hace
filter(predicado) Intermedia Deja pasar solo los que cumplen
map(función) Intermedia Convierte cada elemento en otro
sorted(comparador) Intermedia Ordena
distinct() Intermedia Quita duplicados
limit(n) Intermedia Toma los primeros n
toList() Final Devuelve una lista (inmutable)
count() Final Cuenta los elementos
anyMatch(predicado) Final true si al menos uno cumple
findFirst() Final El primero, dentro de un Optional
forEach(acción) Final Ejecuta algo con cada elemento
collect(Collectors...) Final Arma listas, mapas, agrupaciones o textos

Más ejemplos:

long agotados = productos.stream().filter(p -> p.stock() == 0).count();          // 1

double valorTotal = productos.stream()
    .mapToDouble(p -> p.precio() * p.stock())   // stream de double
    .sum();

boolean hayCaros = productos.stream().anyMatch(p -> p.precio() > 500_000);       // true

Optional<ProductoDto> masBarato = productos.stream()
    .min(Comparator.comparing(ProductoDto::precio));

String nombres = productos.stream()
    .map(ProductoDto::nombre)
    .collect(Collectors.joining(", "));         // "Teclado, Mouse, Monitor, Audífonos"

Map<Boolean, List<ProductoDto>> porDisponibilidad = productos.stream()
    .collect(Collectors.partitioningBy(p -> p.stock() > 0));

Agrupar es muy común en reportes:

record Venta(String ciudad, double total) { }

List<Venta> ventas = List.of(
    new Venta("Medellín", 200_000), new Venta("Bogotá", 150_000), new Venta("Medellín", 50_000));

Map<String, Double> totalPorCiudad = ventas.stream()
    .collect(Collectors.groupingBy(Venta::ciudad, Collectors.summingDouble(Venta::total)));
// {Medellín=250000.0, Bogotá=150000.0}

Cuándo usar streams. Para filtrar, transformar o resumir datos son más claros que un for. Si la lógica necesita varios pasos con estado o te cuesta leerla, un for normal está bien. La legibilidad manda.

13. Maven y estructura de un proyecto

Maven es la herramienta que compila tu proyecto, descarga las bibliotecas que necesita y lo empaqueta para ejecutarlo. Todo proyecto Spring Boot del curso es un proyecto Maven, así que conviene que reconozcas sus piezas antes de la primera clase.

Qué resuelve

Sin Maven tendrías que descargar a mano cada biblioteca (.jar), copiarla al proyecto y compilar con comandos largos. Con Maven declaras qué necesitas en un archivo, pom.xml, y él descarga todo desde Maven Central, incluidas las dependencias de tus dependencias.

Estructura estándar

mi-proyecto/
├── pom.xml                         configuración y dependencias
├── mvnw  y  mvnw.cmd               Maven Wrapper: Maven sin instalarlo
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   └── com/freetech/tienda/
│   │   │       └── TiendaApplication.java   tu código
│   │   └── resources/
│   │       └── application.properties       configuración de la app
│   └── test/
│       └── java/                   pruebas automáticas
└── target/                         lo que genera la compilación (no se sube a Git)

La carpeta de cada paquete debe coincidir con su declaración package, como viste en la sección 6.

El archivo pom.xml

<project>
    <modelVersion>4.0.0</modelVersion>

    <!-- Coordenadas: identifican tu proyecto -->
    <groupId>com.freetech</groupId>
    <artifactId>tienda</artifactId>
    <version>0.0.1-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>21</maven.compiler.release>
    </properties>

    <!-- Bibliotecas que tu código usa -->
    <dependencies>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.11.4</version>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>
  • groupId: la organización, en formato de dominio al revés.
  • artifactId: el nombre del proyecto.
  • version: SNAPSHOT significa "en desarrollo".
  • Cada dependency se identifica con las mismas tres coordenadas.
  • scope test: la dependencia solo se usa en las pruebas.

En un proyecto Spring Boot el pom.xml además declara un parent (spring-boot-starter-parent) que fija versiones compatibles de todas las bibliotecas, y dependencias llamadas starters, como spring-boot-starter-web, que traen todo lo necesario para una API. Spring Initializr te genera ese archivo; no lo escribes a mano.

Comandos

Comando Qué hace
./mvnw compile Compila el código de src/main/java
./mvnw test Compila y ejecuta las pruebas
./mvnw package Genera el .jar en target/
./mvnw clean Borra la carpeta target/
./mvnw spring-boot:run Arranca una aplicación Spring Boot

En Windows usa mvnw.cmd en lugar de ./mvnw. El Maven Wrapper descarga la versión correcta de Maven la primera vez, así que no necesitas instalar Maven aparte.

La primera vez tarda. El primer comando descarga muchas bibliotecas a la carpeta .m2 de tu usuario. Las siguientes ejecuciones son rápidas porque las reutiliza.

Crear un proyecto Maven en VS Code

  1. Ctrl+Shift+P (o Cmd+Shift+P en macOS) y ejecuta Java: Create Java Project.
  2. Elige Maven y luego maven-archetype-quickstart.

14. El puente a Spring Boot

Todo lo que aprendiste aparece en una aplicación Spring Boot: clases, interfaces, inyección por constructor, records, colecciones, Optional y excepciones. Esta sección te muestra una API pequeña para que en la semana 1 reconozcas cada pieza; no tienes que escribirla todavía.

Las capas de una API

Cliente (navegador, Postman o app) envía GET /api/productos/1
ControllerRecibe la petición HTTP y devuelve JSON. No tiene lógica de negocio.@RestController
ServiceReglas de negocio y validaciones. Lanza excepciones cuando algo no cumple.@Service
RepositoryLee y guarda en la base de datos. Es una interfaz que Spring implementa.JpaRepository
PostgreSQL

Cada capa solo conoce a la de abajo, y la recibe por el constructor. Es el mismo patrón de ServicioPedidos y Notificador de la sección 8.

Una API completa en cuatro archivos

// ProductoDto.java: el JSON que entra y sale (sección 9)
public record ProductoDto(Long id, String nombre, double precio) { }

// ProductoRepository.java: una interfaz que Spring implementa sola (sección 8)
public interface ProductoRepository extends JpaRepository<Producto, Long> {
    List<Producto> findByPrecioLessThan(double precio);   // Spring deduce la consulta del nombre
}

// ProductoService.java: lógica de negocio
@Service
public class ProductoService {

    private final ProductoRepository repository;

    public ProductoService(ProductoRepository repository) {   // inyección por constructor
        this.repository = repository;
    }

    public ProductoDto buscarPorId(Long id) {
        Producto p = repository.findById(id)                     // devuelve Optional (sección 10)
            .orElseThrow(() -> new ProductoNoEncontradoException(id));   // sección 11
        return new ProductoDto(p.getId(), p.getNombre(), p.getPrecio());
    }

    public List<ProductoDto> listarBaratos(double maximo) {
        return repository.findByPrecioLessThan(maximo).stream()  // streams (sección 12)
            .map(p -> new ProductoDto(p.getId(), p.getNombre(), p.getPrecio()))
            .toList();
    }
}

// ProductoController.java: la puerta HTTP
@RestController
@RequestMapping("/api/productos")
public class ProductoController {

    private final ProductoService service;

    public ProductoController(ProductoService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public ProductoDto buscar(@PathVariable Long id) {
        return service.buscarPorId(id);
    }

    @GetMapping
    public List<ProductoDto> baratos(@RequestParam double maximo) {
        return service.listarBaratos(maximo);
    }
}

Observa que nunca aparece new ProductoService(...) ni new ProductoController(...). Spring ve las anotaciones, crea un objeto de cada clase y le pasa a cada constructor lo que pide. A esos objetos que maneja Spring se les llama beans.

Las anotaciones

Una anotación (@Algo) es una etiqueta que le da información a Spring o al compilador sobre una clase, un método o un parámetro. Ya conoces @Override. Las primeras que verás en el curso:

Anotación Dónde va Qué le dice a Spring
@SpringBootApplication La clase con el main Aquí arranca la aplicación
@RestController Una clase Atiende peticiones HTTP y responde JSON
@RequestMapping("/ruta") Una clase Prefijo de las rutas de ese controlador
@GetMapping, @PostMapping, @PutMapping, @DeleteMapping Un método Qué verbo HTTP y qué ruta atiende
@PathVariable Un parámetro Toma el valor de la ruta, como el 1 de /productos/1
@RequestParam Un parámetro Toma un valor de la URL, como ?maximo=100000
@RequestBody Un parámetro Convierte el JSON recibido en un objeto
@Service Una clase Es un servicio de negocio
@Entity Una clase Representa una tabla de la base de datos

Mensaje o síntoma Causa Solución
cannot find symbol Nombre mal escrito, variable fuera de alcance o falta un import Revisa mayúsculas y el bloque donde la declaraste; en VS Code Ctrl+. sugiere el import
class X is public, should be declared in a file named X.java El archivo y la clase pública se llaman distinto Renombra el archivo o la clase para que coincidan
